# Test Plan: UI E2E Automation (SauceDemo)

## 1. Мета
Перевірити критичні бізнес-флоу вебдодатку на рівні UI E2E автотестами:
- авторизація користувача;
- базова взаємодія з каталогом товарів;
- перехід до checkout після додавання товару в кошик.

## 2. Scope
### In scope
- Логін валідними обліковими даними.
- Негативні сценарії логіну (неправильний пароль, заблокований користувач).
- Додавання товару в кошик.
- Перехід з кошика до сторінки checkout.

### Out of scope
- Повний позитивний checkout до завершення замовлення.
- Кросбраузерне тестування (наразі Chrome).
- Тестування продуктивності та безпеки.

## 3. Тестове оточення
- ОС: локально (Windows), CI (Ubuntu).
- Browser: Google Chrome (headless у CI).
- Інструменти: Python, Pytest, Selenium, webdriver-manager, GitHub Actions.
- Тестовий стенд: `https://www.saucedemo.com`.

## 4. Рівні та типи тестів
- **Smoke**: базова перевірка доступності критичних флоу.
- **Regression**: перевірка розширених основних сценаріїв.

## 5. Критерії входу
- Доступний тестовий стенд.
- Валідні тестові дані (користувачі SauceDemo).
- Свіжий білд застосунку в середовищі тестування.

## 6. Критерії виходу
- Усі smoke-тести зелені.
- Критичні дефекти відсутні або задокументовані з погодженим workaround.
- Regression suite не має blocker/critical дефектів.

## 7. Ризики
- Флакі через нестабільні локатори або затримки UI.
- Зовнішні зміни демо-стенду, що ламають селектори.
- Нестабільність мережі під час виконання CI.

## 8. Мітигації
- Використання explicit waits замість `sleep`.
- Централізація локаторів у Page Objects.
- Збір артефактів падіння (screenshot + page source).

## 9. Артефакти
- `reports/ui_failures/*.png`
- `reports/ui_failures/*.html`
- CI run logs в GitHub Actions.

## 10. Відповідальності
- Automation Engineer: підтримка фреймворку, написання тестів, triage падінь.
- QA/Team: валідація багів, пріоритезація, фідбек по покриттю.
